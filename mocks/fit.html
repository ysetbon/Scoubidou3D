The sort reads the geometry that is current, so it works the same before a fit and after one — the fitted row is not pinned to the top, it earns the top. Change the key in the sidebar and the same rows reorder; change the fit policy and the fitted row moves with it. And it is worth something on its own: the engine's own ranking scores gap variance and never looks at length, so the cell it adopts is — px out of flush while a cell on the same grid, which its search had already evaluated and discarded, is —. Sorting costs nothing and recovers most of the stagger before any fitting happens.

Same five segments as a run, same descriptorPath(), same version in the key — so a judgement made against one engine can never be read as one made against another. /mxn/ asks for picks before run and opens on the ★ best, labelled, with the engine's own answer one press away. The body is the judgements, not the rings — each is a pick, about 200 bytes:

★ best is the one /mxn/ opens on, and there is only ever one — marking this demotes j-2b10 to valid. ★ implies ✓.

Written to localStorage and into the export first, then to the Worker. The button reports which of the two happened, not one "Saved".

Nothing unattended writes a verdict. Not the fitter, not a batch — a judgement with no chooser is refused before it is sent, so the only two states a parameter set can be in are you chose and the engine did. source is a fact about where the geometry came from and the machine may write it; verdict is yours. A judgement whose engineCommit or run timestamp no longer matches the shelf is shown as stale and not applied: an extension and an angle mean something only against the checkpoint they were measured on.
